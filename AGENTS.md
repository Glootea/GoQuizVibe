# GoQuizVibe - образовательная платформа с тестами

## Подходы к разработке
- Перед добавлением кода, проверь, может данная функциональность уже есть в проекте и может быть переиспользована с небольшими изменениями
- Старайся использовать HTMX first подход + логику на сервере, а прибегать к JS только при крайней необходимости (например, интерактивность таймера на странице)
- Используй параллельных субагентов для выполнения частей задачи
- Используй ./tmp вместо ~/tmp для временных файлов. Не читай файлы вне изначальной директории
- При изменении кода нужно удалить теперь неактуальный код

## Stack
Go, Templ + HTMX + tailwind, podman-compose, PostgreSQL + sqlc, MinIO (S3 compatible), Redis 

## Конфигурация
.env + чтение в backend/shared/config/config.go

## Локализация
Файлы локализации в @backend/shared/locales/{lang}/LC_MESSAGES/default.po -> `go tool gettextgocodegen -dir locales -lang ru -package locales` для генерации локализованных строк. Убедись, что при генерации нет коллизий, измени имена переменных, если нужно.

## Обработка ошибок
Все ошибки обрабатываются явно, пробрасываясь выше по стэку вызовов, добавляя полученный на данном уровне контекст. На каждый route добавлен middleware обработки ошибок Например:
```go
func serviceFunc(args ArgsType) (value, error) {
    val, err := someCall()
    if  err != nil {
        return nil, errors.Join(errors.New("Failed to call someCall in serviceFunc"), err)
    }
    return value, nil
}
```

## Запуск сервера
`python3 scripts/run_bg.py` для запуска сервера в фоне, чтобы вернуть управление после старта. Уничтожь процесс при необходимости. Логи доступны в ./output.txt

## База данных
PostgreSQL + sqlc (`go tool sqlc generate`)


## Деление на слои
- handlers - обработка HTTP запросов, чтение аргументов, запись body и headers, делегирование остальной работы services
- services - бизнес-логика, подготовка данных из разных источников
- repositories - доступ к данным

## UI
`make generate` для генерации всего необходимого: локализации, шаблонов, tailwind классов и их сортировки
Выделяй логические/семантические компоненты для дальнейшего переиспользования и повышения читаемости кода
Используй `go tool templ generate` для генерации шаблонов

## Static
Статические файлы (CSS, JS, изображения) хранятся в `backend/static` 

## Test
Покрытие unit тестами сервисов должно быть высоким (>= 80%), остальные тесты не нужны
